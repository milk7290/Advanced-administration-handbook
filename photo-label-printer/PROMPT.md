# 프롬프트: 밥테일베이커리 사진 즉석 인쇄 웹앱 (YHK 블루투스 프린터)

아래 내용을 그대로 AI 코딩 어시스턴트에 붙여 넣으면 이 프로그램을 동일하게 만들 수 있도록 작성했습니다.
(결과물: 의존성 없는 단일 `index.html`. 로고·글꼴을 모두 파일 안에 내장하여 인터넷 없이 동작)

---

## 0. 역할과 목표

너는 시니어 웹 프론트엔드 개발자다. **카페/베이커리 매장에서 손님이 직접 쓰는 "사진 즉석 인쇄 키오스크" 웹앱**을 만들어라.
손님이 폰/태블릿 화면의 큰 버튼으로 사진을 찍으면, **블루투스(BLE)로 연결된 소형 감열 프린터**가 바로 그 사진을 인쇄한다.
프린터는 자동 커팅이 없으므로 손님이 직접 뜯어야 하고, 여러 장을 뽑을 때는 "한 장 인쇄 → 손님이 뜯고 확인 → 다음 장" 순서로 진행한다.

### 기술 제약
- **단일 파일 `index.html`** (HTML+CSS+JS 한 파일, 프레임워크/빌드/CDN/외부 요청 **전부 금지**). 인터넷이 없어도 완전히 동작해야 한다.
- Web Bluetooth + `getUserMedia`를 사용한다. (HTTPS 또는 `http://localhost`에서 동작)
- 지원 환경: 안드로이드 Chrome, 아이폰 **Bluefy** 브라우저(Safari/Chrome iOS는 Web Bluetooth 미지원).
- 화면 문구는 **한국어**. 모바일 세로 화면 우선(폭 390px 기준), 다크 테마.
- 바닐라 JS, `'use strict'`, 외부 라이브러리 없음.

## 1. 대상 하드웨어 (반드시 이 사양을 따를 것)

- 프린터: 알리익스프레스 "WalkPrint(Walkprinter) 앱" 계열 YHK 포켓 감열 프린터. BLE 광고 이름은 `YHK-XXXX`(예: `YHK-0B6A`). 58mm 용지, **384도트 폭(48바이트/줄)**, 203dpi 근처(8도트/mm).
- BLE GATT:
  - 서비스(ISSC 투명 UART): `49535343-fe7d-4ae5-8fa9-9fafd205e455`
  - 쓰기 특성(Write + WriteWithoutResponse): `49535343-8841-43f4-a8d4-ecbe34729bb3` ← **인쇄 데이터는 여기로**
  - 그 외: `...1e4d...`(Notify), `...6daa...`(Write), `...aca3...`(Notify, Write)
- **인쇄 명령(검증된 사실)**:
  - 초기화: `1B 40`
  - 농도: `1D 49 F0 nn` (nn: 1~40, 기본 15)
  - 래스터 한 줄: `1D 76 30 00 30 00 01 00` + 48바이트 (= 56바이트 패킷). 비트 1=검정, MSB=왼쪽 픽셀
  - 종료/용지 이송: `0A` 를 N개(기본 4개)
  - ⚠ **핵심 함정**: 이 프린터는 **BLE 패킷 1개를 명령 1개로 해석**하고, `GS v 0`은 **패킷당 한 줄만 인쇄**한다. 이미지를 한꺼번에 이어서 보내면 첫 줄만 찍혀 가는 줄무늬만 나온다. 따라서 **반드시 "한 줄 = 한 번의 write(56바이트)"** 로 전송한다.
  - 전송은 `writeValueWithResponse`(응답 대기)를 기본으로 하여 패킷 유실을 막는다. (Write 속성이 없으면 `writeValueWithoutResponse` + 최소 20ms 간격)
  - ESC/POS(`GS v 0` 연속 전송), CPCL, TSPL 모드도 **관리자용 대체 프로토콜**로 남겨라. 기본값은 YHK 모드.
- 이 프린터에서는 일반 텍스트 인쇄(ESC/POS 텍스트, CPCL TEXT, TSPL TEXT)가 **출력되지 않는다**. 글자/로고는 반드시 **이미지(비트맵)로 렌더링**해서 보내라.

## 2. Web Bluetooth 연결 구현 (Bluefy 호환 주의사항)

Bluefy는 `requestDevice` 옵션의 형식에 매우 민감하다. 다음을 지켜라.

1. 옵션 안의 서비스 UUID는 **전부 소문자 128비트 문자열**로 쓴다. 숫자(`0xff00`)와 문자열을 섞지 말고, **중복 UUID를 제거**하라. (중복/긴 목록 때문에 `Request payload could not be parsed` 오류 → 예외값이 숫자 `2`로 나옴)
2. 아래 순서로 **연속 시도**하고, 각 시도의 성공/실패를 로그에 남긴다(`NotFoundError`=사용자 취소면 즉시 중단):
   1. `{ filters:[{namePrefix:'YHK'}], optionalServices:[ISSC] }`  ← 기본(선택창에 YHK 기기만 표시)
   2. `{ acceptAllDevices:true, optionalServices:[ISSC] }`
   3. `{ acceptAllDevices:true, optionalServices:[흔한 프린터 서비스 전체(중복 제거)] }` (ff00, ffe0, fee7, ae30, 18f0, ff12, fff0, fe59, ISSC, e7810a71-73ae-499d-8c15-faa9aef0c3f2)
   4. `{ acceptAllDevices:true, optionalServices:[ae30, ff00, 18f0, ffe0, fee7] }`
   5. `{ acceptAllDevices:true }` (마지막 수단; 서비스 접근 불가 경고)
3. 서비스를 `optionalServices`에 넣지 않으면 연결은 되지만 서비스가 보이지 않는다("쓰기 가능한 특성을 찾지 못함").
4. 연결 후 `getPrimaryServices()` → 실패 시 알려진 UUID를 하나씩 `getPrimaryService()`. 모든 특성의 `write/writeWithoutResponse` 여부를 로그에 `svc … chr … [속성]` 형식으로 출력.
5. 쓰기 특성 선택 우선순위: UUID에 `49535343-8841` 포함(10점) 등 알려진 값 > writeWithoutResponse 지원. 관리자 설정에서 특성을 수동 선택 가능하게(드롭다운, 기본 "자동").
6. 오류는 `e.name: e.message`, 값이 숫자/문자열이면 `String(e)`로 사용자에게 **단계명과 함께** 표시(`연결 실패 [장치 선택]: …`). `gattserverdisconnected` 시 상태를 "연결 끊김"으로 바꾸고 인쇄 버튼을 비활성화.
7. 연결/해제는 **관리자 화면**에서만 한다(브라우저 정책상 사용자 제스처로 선택창을 띄워야 함). 페이지를 새로고침하면 다시 연결해야 한다.

## 3. 이미지 처리 파이프라인

촬영 → 인쇄용 비트맵 생성은 다음 순서다(`render()`).

1. 소스(비디오 프레임 캔버스 또는 불러온 이미지)를 **폭 W(기본 384)** 로 축소(높이는 비율 유지, 90° 회전 옵션 시 가로/세로 교환).
2. 그레이스케일 `0.299R+0.587G+0.114B` → 대비/밝기 보정(대비 공식 `f=(259(c+255))/(255(259−c))`, 기본 대비 30, 밝기 0).
3. 이진화: **Floyd–Steinberg 디더링**(사진용, 기본) 또는 임계값 128(글자/로고용). 색 반전 옵션.
4. **맨 위에 머리띠(로고+날짜) 비트맵을 붙인다**(아래 5장). 머리띠는 디더링하지 않고 `(R+G+B)/3 < 150` 임계값으로 또렷하게.
5. 합성 결과를 미리보기 캔버스에 흑백으로 표시하고 `{w,h,data(1=검정)}`로 보관.
6. 1비트 패킹: 한 줄 `ceil(w/8)`바이트, MSB=왼쪽. YHK 모드는 줄 바이트가 48을 넘으면 잘라내고 모자라면 0으로 채움.

## 4. 화면 구성

### 4-1. 손님 화면(키오스크, 기본 화면)
세로 flex 레이아웃, 높이 100%, 최대폭 560px 중앙.
- **맨 위 줄**: 왼쪽 **밥테일베이커리 로고**(높이 56px, 다크 배경이라 CSS `filter:invert(1)`로 흰색 표시), 오른쪽에 **날짜**(귀여운 글꼴, 26px, 따뜻한 크림색 `#ffd9a8`)와 **⚙ 버튼**(투명, 흐리게).
- **카메라 영역**(`<video playsinline muted autoplay>`, object-fit:cover, 둥근 모서리 20px): 왼쪽 위에 상태칩("● 프린터 준비됨"=초록 / "● 프린터 연결 필요"=빨강), 오른쪽 위에 🔄 카메라 전환 버튼(전/후면 `facingMode`).
  - 카메라 불가 시 안내문("카메라를 사용할 수 없어요. 브라우저의 카메라 권한을 허용해 주세요.").
  - 카운트다운 오버레이(큰 숫자 140px + **취소 버튼**), 촬영 시 흰색 플래시 효과(0.2초).
- **힌트 문구**: 준비됨 → "버튼을 누르면 사진이 바로 인쇄돼요" / 미연결 → "프린터가 준비되지 않았어요. 직원에게 알려 주세요".
- **인쇄 장수 선택**: `인쇄 장수  [−] N [＋]  장`. 원형 52px 버튼, 최소 1 ~ 최대(설정, 기본 5). 한 세션이 끝나면 1로 되돌린다.
- **큰 촬영 버튼**: 전체폭, 알약 모양, 파란색(`#4da3ff`), "📸 사진 찍기", 프린터 미연결 또는 진행 중이면 비활성화.
- 화면 꺼짐 방지(`navigator.wakeLock`, 탭 복귀 시 재요청). 텍스트 선택/확대 방지, 탭 하이라이트 제거.

### 4-2. 진행 오버레이(전체 화면, 반투명 검정 92%)
상단에 방금 찍은 인쇄용 이미지 미리보기(최대 높이 30vh, 흰 배경), 그 아래 제목·부제·(큰 숫자)·경고박스·버튼.

**장마다 4단계**로 진행한다(전체 장수가 2장 이상이면 제목에 ` (i/N장)` 표시):
1. **인쇄 중**: 제목 "인쇄 중이에요…", 부제 `NN% · 약 N초 남음`(진행률 5% 이상부터, 경과시간×(1−p)/p로 추정), **빨간 경고박스** "⚠️ 반드시 '출력 완료' 메시지가 나온 이후에 사진을 뜯어 주세요!", **[취소]**.
2. **마무리 중**: 인쇄 데이터 전송이 끝난 직후 `마무리 대기(초, 기본 3)` 동안 큰 숫자 카운트다운. 제목 "마무리 중이에요…", 부제 "용지가 다 나올 때까지 기다려 주세요.\n아직 사진을 뜯지 마세요!", 경고박스 유지, **[취소]**.
3. **✅ 출력 완료!**: 부제 "이제 사진을 뜯어 주세요 ✂️\n뜯으셨으면 확인을 눌러 주세요"(다음 장이 있으면 "(확인 후 N번째 장을 인쇄해요)" 추가). **[확인]**(큰 파란 알약), 다음 장이 남았을 때만 **[취소]**. **이 단계에서 처음으로 "뜯어 주세요" 문구를 보여 준다.**
4. **다음 장 준비**(확인을 누른 뒤, 남은 장이 있을 때만): `다음 장 대기(초, 기본 3)` 큰 숫자 카운트다운, 제목 "다음 장 준비 중이에요", 부제 "N번째 장을 곧 인쇄해요", **[취소]**. 끝나면 다음 장 1단계로.
- 마지막 장의 [확인]을 누르면 오버레이를 닫고 첫 화면으로 복귀.
- **방치 처리**: 3단계에서 2분간 입력이 없으면 남은 장은 인쇄하지 않고 종료(종이 낭비 방지).
- **취소 동작**(모든 단계에서 가능): 카운트다운/대기는 즉시 종료(0.1초 단위 폴링), **전송 중이면 전송 루프를 즉시 중단**하고 프린터에 `1B 40`을 한 번 보낸다. 취소하면 "취소했어요"를 1.5초 보여 주고 복귀. 남은 장은 인쇄하지 않는다.
- 인쇄 실패 시 "인쇄에 실패했어요 / 직원에게 알려 주세요" + [확인](30초 후 자동 종료).
- 한 번 촬영한 이미지 한 장을 N번 반복 인쇄한다(재촬영 없음).
- 모든 종료 경로에서 `finally`로 상태 초기화(진행중 플래그, 대기 해제, 오버레이 숨김, 장수 1로, 버튼 갱신).

### 4-3. 관리자 화면(비밀번호 `1234`)
- 손님 화면의 ⚙ → 비밀번호 모달(숫자 키패드 입력, `type=password inputmode=numeric`, Enter로 확인, 틀리면 "비밀번호가 맞지 않아요") → 전체 화면 관리자 패널. 맨 위 [닫기].
- 비밀번호는 코드에 기본 `1234`, 관리자 패널에서 **숫자 4~12자리로 변경** 가능(`localStorage` 키 `plp_pw`). (클라이언트 측 잠금일 뿐이며 보안 기능이 아님을 README에 명시)
- 패널 구성:
  1. **프린터 연결 / 연결 해제**, 상태 문구(성공=초록, 실패=빨강)
  2. 미리보기 캔버스(마지막 인쇄 이미지, 흑백, `image-rendering:pixelated`), 버튼: **마지막 사진 인쇄 / 테스트 인쇄(체크무늬) / ⏹ 중지 / 사진 파일 불러오기 / 언어 확인(텍스트: ESC/POS·CPCL·TSPL 샘플을 2.5초 간격으로 전송)**
  3. **인쇄 설정**(아래 표)
  4. **관리자 비밀번호 변경**
  5. **로그 창**(회색 monospace, 연결/전송 로그)

### 로고
- 첨부된 `밥테일베이커리` 로고 PDF(검은 글자 "BOBTAIL BAKERY / made from scratch! / SOKCHO CITY", 벡터)를 사용한다.
- PDF를 **1200dpi로 래스터화**(`pdftoppm -r 1200 -png`) → 여백 자르기(+패딩) → 폭 900px로 축소 → **밝기를 알파 채널로 변환**(색은 검정, 글자=불투명/배경=투명) → PNG → base64로 `DEFAULT_LOGO` 상수에 **내장**.
- 손님 화면에서는 이 투명 PNG에 `filter:invert(1)`을 적용해 흰 로고로 표시. 인쇄 시에는 흰 캔버스 위에 그려 임계값 처리.
- **로고 변경**: 관리자가 이미지를 올리면 폭 700px 이하로 줄이고 같은 방식(밝기→알파, 검정색)으로 변환해 `localStorage('plp_logo')`에 PNG dataURL로 저장. 용량 초과 시 알림. **기본 로고** 버튼으로 복원. 흰 배경+검은 글자 이미지를 권장한다고 안내.
- 설정 화면에는 현재 로고를 흰 배경 칩에 미리보기.

### 상호명(배포 대응)
- 인스타 등으로 다른 매장에 배포할 수 있도록 **상호명 입력**을 지원한다. 설정에 `머리띠 표시 방식`(로고 이미지 / 상호명 글자)과 `상호명`(최대 30자, 입력 즉시 반영·저장)을 둔다.
- 로고 방식이어도 로고 이미지가 없으면 상호명 글자로 자동 대체. 상호명이 비어 있으면 왼쪽 요소 없음(날짜만).
- 화면: 흰색 굵은 글자(최대 2줄, 22px, 시스템 한글 글꼴 `Apple SD Gothic Neo/Noto Sans KR/Malgun Gothic`).
- 인쇄: 로고 자리에 **굵은 글자(800)** 로 그린다. 날짜 폭을 뺀 영역 안에서 **최대 2줄에 들어가는 가장 큰 글자 크기(46→18px)** 를 자동 선택하고, 그래도 넘치면 18px에서 말줄임(…).
- 상호명은 임의의 글자이므로 날짜용 부분 글꼴이 아니라 **기기 기본 한글 글꼴**을 쓴다(오프라인에서도 동작).
- **배포용 빌드**: `index.html`에서 내장 로고를 1×1 투명 PNG로 바꾸고, 기본 방식=상호명 글자, 기본 상호명="우리 가게", 제목="즉석 사진 인쇄"로 바꿔 `index.public.html`을 만든다. 빌드 후 `BOBTAIL/밥테일` 문자열이 남지 않았는지 검사한다.

### 날짜
- 현재 날짜(`new Date()`), 선택한 형식. 한국어 요일은 `일월화수목금토`. 1분마다 화면 날짜 갱신. 촬영 시점에 인쇄용 머리띠에 다시 계산.
- **글꼴은 전부 내장**: Google Fonts에서 6개 TTF를 받아 `fonttools`(`pyftsubset`)로 필요한 글자만 남기고(`0123456789.-/: 년월일()월화수목금토일`) base64 `@font-face`로 CSS에 삽입(총 약 75KB). 외부 `<link>`/요청 금지. (Gaegu는 `font-weight:700` 면, 나머지는 400)
- 캔버스에 쓸 때는 `document.fonts.load()`로 로드를 보장하고 `"선택글꼴","Jua",sans-serif` 폴백.

### 인쇄용 머리띠 레이아웃
- 로고/날짜 둘 중 하나라도 켜져 있으면 사진 **위에** 머리띠를 붙인다. 폭=용지 폭 W, 패딩 10px.
- 로고: **왼쪽**, 폭 = W×(로고 크기%), 비율 유지, 세로 중앙.
- 날짜: **오른쪽 정렬**, 글자 크기 = W×0.085(384px일 때 약 33px), 세로 중앙, 검정.
- 높이 = max(로고 높이, 글자 높이+8) + 패딩×2. 둘 다 꺼져 있으면 머리띠 없음.

## 6. 상태 저장

- `localStorage` 접근은 항상 `try/catch`. 설정(`plp2`), 로고(`plp_logo`), 비밀번호(`plp_pw`).
- 설정 입력의 `change` 이벤트마다 저장 → 화면 머리띠 갱신 → 미리보기 재생성. 밝기/대비 슬라이더는 `input` 이벤트로 실시간 반영.

## 8. 검증 (구현 후 반드시 수행하고 결과를 보고)

실제 프린터가 없으면 **Playwright(Chromium) + 가짜 블루투스/카메라**로 아래를 자동 검증한다.
- 실행 옵션: `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`, 뷰포트 390×844, `permissions:['camera']`.
- `addInitScript`로 `navigator.bluetooth.requestDevice`를 가짜 장치(이름 `YHK-TEST`)로 대체. 쓰기 특성은 `writeValueWithResponse`/`WithoutResponse` 호출 횟수·길이를 기록.

체크리스트:
1. 연결 전: 촬영 버튼 비활성화, 칩 "연결 필요". 틀린 비밀번호 거부 / `1234` 통과.
2. 연결 후: 칩 "준비됨", 촬영 버튼 활성화.
3. 1장 인쇄: 패킷 구성 `[2바이트 초기화, 4바이트 농도, 56바이트×(머리띠+사진 높이), 4바이트 이송]` 확인(예: 353패킷). 각 래스터 패킷이 정확히 56바이트이고 헤더가 `1D 76 30 00 30 00 01 00`.
4. 2장: 1장 완료 후 "출력 완료" 화면에서 **확인 클릭 전에는 추가 write가 없어야** 하고, 확인 후 카운트다운을 거쳐 2번째 인쇄. 마지막 장에는 [취소]가 없고 [확인]만.
5. 단계 문구 순서: 인쇄 중(경고박스 O, 남은시간 표시) → 마무리(큰 숫자, 경고박스 O) → 출력 완료(확인 O, 경고박스 X) → 다음 장 준비(큰 숫자).
6. 취소: 카운트다운 중 / 인쇄 중(write 수가 전체보다 훨씬 적은 시점에 멈춤) / 뜯기 대기 중 / 다음 장 대기 중, 각각 이후 추가 인쇄가 없어야 함. 취소 후 촬영 버튼 재활성화.
7. 머리띠: 켜면 인쇄 캔버스 높이가 늘고(로고 왼쪽/날짜 오른쪽), 끄면 줄어듦. 로고 업로드·기본 복원 동작.
8. **오프라인**: `offline:true` 컨텍스트에서 외부 `http(s)` 요청 0건, 6개 글꼴 모두 `document.fonts.check()` 통과 및 서로 다른 글자 폭.
9. 콘솔/pageerror 0건. 스크린샷으로 손님 화면·진행 오버레이·관리자 화면 육안 확인(제목/칩이 한 줄로 줄바꿈 없이 보일 것).

## 9. 알려진 한계와 현장 튜닝 (README/최종 보고에 포함)

- 실제 프린터로는 현장에서 테스트해야 한다. 인쇄 위쪽이 번지면 프린터를 껐다 켜고 전송 간격(10~20ms)을 올린다. 너무 연하거나 진하면 농도(1~40)·밝기·대비 조정.
- 사진이 뜯기 좋게 나오지 않으면 "인쇄 후 용지 이송(줄)"을 늘리고, 안내가 인쇄보다 빨리 뜨면 "마무리 대기(초)"를 늘린다.
- 비밀번호는 클라이언트 측 간이 잠금이다. 페이지 새로고침/브라우저 재시작 시 프린터를 관리자 화면에서 다시 연결해야 한다.
- 폰 설정에서 화면 자동 꺼짐을 길게 하고 충전기를 연결해 둔다.

최종 응답에는 (1) 만든 파일, (2) 위 검증 결과(통과/실패와 수치), (3) 시험하지 못한 부분(실제 프린터·실제 폰)을 **사실대로** 구분해서 보고하라.
